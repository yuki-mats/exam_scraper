# sc category.json 整備方針

## 根拠と対象範囲

`category.json` は、情報処理安全確保支援士の全対象年度・午前Ⅰ・午前Ⅱを横断して設計する。今回の入力は、2009年春期から2025年秋期までの99個の`00_source`であり、各問題に保存された`categoryHierarchy`の3階層を漏れなく確認した。`00_source`、既存の問題ID、問題側の`questionSetId`はこの工程では変更しない。

分類の上位集計軸は、問題データに保存された公式系統の「ストラテジ系」「テクノロジ系」「マネジメント系」とする。これらはfolderへ直接対応させるには範囲が粗いため、同じ`categoryHierarchy`の第2階層を学習上のfolderへ分割した。第1階層からfolderへの対応は、`category.json`の`metadata.officialCategoryMappings`へ記録し、公式系統へ再集計できるようにした。

## folder と questionSet の境界

- folderは第2階層の分野とし、年度、試験区分、午前Ⅰ・午前Ⅱ、問題番号では分割しない。
- questionSetは第3階層の出題小分類とし、問題を間違えた受験者が復習する専門単元として扱う。問題文の主題が技術実装、管理、法務のいずれにあるかは、保存された第3階層と既存の資格固有方針を合わせて判断する。
- 「セキュリティ」はSCの中心分野だが、情報セキュリティ、対策、管理、実装、評価を一つにまとめず、出題上の学習境界を保持する。法令の規律を直接問う問題は「法務 > セキュリティ関連法規」へ置く。
- システム開発技術とソフトウェア開発管理技術、システム戦略とシステム企画・要件定義は、工程・責務が異なるため別folderとする。サービスマネジメント、システム監査、プロジェクトマネジメントも別folderとする。
- 小分類が少数年度にしか現れない場合でも、公式分類上の意味が独立しており、近接分野へ統合すると復習先の説明が曖昧になるものは独立questionSetとして残す。将来の追加年度を同じIDへ収容できるようにする。

## ID と運用

folder IDとquestionSet IDは`sc_`接頭辞のASCII IDとし、表示名・年度・試験区分をIDへ含めない。今回新規に作成するため、folder番号とfolder内のquestionSet番号を固定し、今後の表示名の改善とIDを分離する。`questionCount`は04で問題紐付けが確定するまで0とし、問題側成果物、merge、convert、upload-readyはこの工程では生成しない。

03c完了後はschema-only dry-runを行い、foldersとquestionSetsの非空、一意ID、folder参照、公式系統mappingの網羅性を確認する。問題単位の分類と件数反映は04の責務である。

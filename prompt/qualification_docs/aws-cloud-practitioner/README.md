# AWS Certified Cloud Practitioner（CLF-C02）

この資格の03解説工程は、全資格共通の[`03_prompt_add_explanationText.md`](../../03_prompt_add_explanationText.md)を正本とし、本資料でAWS固有の用語、判断軸、公式資料、八つの学び方の適用例を補います。試験範囲と取得データの構造は[`01_exam_profile.md`](01_exam_profile.md)、問題集分類は[`03_category_preparation.md`](03_category_preparation.md)を参照します。

## 解説の資格固有調整

- サービス名、機能名、設定名はAWS公式表記を使い、初出では役割を平易に説明する。略称だけで済ませない。
- 正答と解説は、実行時点のAWS公式ドキュメント又は公式サービスページで確認する。取得元の解説、検索結果、以下の例を事実の正本にしない。
- 容量、上限、料金、購入オプション、提供状況、名称は変わり得る。公式仕様と入力の選択肢・正答が一致しない場合は03でつじつまを合わせず、問題文・選択肢を扱う05、正答を扱う02aへ戻す。
- `explanationReferences`は実際に確認したAWS公式一次資料のうち、判断に必要な1〜3件へ絞る。
- 次の例は、主分類を選ぶ判断と解説の情報順をそろえるために使う。同じ語順を繰り返すための固定文型ではない。
- 例では分類の境界が分かるよう一つの対象肢を示す。実際の`explanationText`は共通03の契約に従い、`true_false`は各肢、`flash_card`と`group_choice`は問題全体で1件にする。
- 補足質問は各例とも0件を標準とする。基本解説だけで正答理由と誤答との差を理解できるなら追加しない。

## 八つの学び方の適用例

### 1. 用語と基本を押さえる（`terms_basics`）

- 出典: `question_ping-t-76_39411.json#0`
- 問題: AWS Lambdaの主な用途として正しいものはどれか。
- 見分ける対象: 「複数AWSアカウントの組織管理」はLambdaの用途ではない。
- 分類の判断理由: AWS Lambdaという一つのサービスの基本的な役割を知っていれば判断できる。誤りを直すために別サービスへ触れても、比較そのものが主題でなければ「違いを整理する」にはしない。
- 解説の構成: `Lambdaの役割 → 平易な定義 → 誤った用途の正しい対応先`

出力例（`flash_card`の問題単位）:

> 正しい。AWS Lambdaは、利用者がサーバーを準備・管理せずにプログラムのコードを実行できる、サーバーレスコンピューティングサービスである。複数のAWSアカウントを組織としてまとめて管理するのは、AWS Organizationsの役割である。

公式資料: [AWS Lambda](https://aws.amazon.com/jp/lambda/)、[AWS Organizations](https://aws.amazon.com/jp/organizations/)

### 2. 違いを整理する（`differences_relationships`）

- 出典: `question_ping-t-76_39578.json#0`
- 問題: AWS IAMのポリシーについて、正しい説明はどれですか。
- 対象肢: IDベースのポリシーは、S3バケットやSQSキューなどのAWSリソースにアタッチする。
- 分類の判断理由: IDベースポリシーとリソースベースポリシーの「アタッチ先の違い」が正誤を分ける中心である。
- 解説の構成: `正しい対応 → IDベースポリシーの対象と役割 → リソースベースポリシーとの差`

出力例:

> 間違い。正しくは、IDベースのポリシーは、IAMユーザー、IAMグループ、IAMロールにアタッチし、そのIDが実行できる操作を定める。S3バケットやSQSキューなどのAWSリソースにアタッチするのは、リソースベースのポリシーである。

公式資料: [ID ベースのポリシーとリソースベースのポリシー](https://docs.aws.amazon.com/ja_jp/IAM/latest/UserGuide/access_policies_identity-vs-resource.html)

### 3. 条件を押さえる（`conditions_scope`）

- 出典: `question_keepitup-CLF203C040.json#0`
- 問題: Amazon S3の基本的な特徴として正しいものを選択してください。
- 対象肢: 1つのオブジェクトには容量上限がなく、任意のサイズで保存できる。
- 分類の判断理由: S3の概要ではなく、「1オブジェクトに保存できる数値範囲」が正誤を分ける。
- 解説の構成: `現在の上限 → オブジェクトの平易な説明 → バケット全体と1オブジェクトの範囲の違い`

出力例:

> 間違い。正しくは、Amazon S3の1つのオブジェクトは、0バイトから最大50TBまで保存できる。ここでオブジェクトとは、S3に保存する1つのファイルに相当する。S3に多数のファイルを保存できることと、1つのファイルを無制限の大きさで保存できることは別である。

公式資料: [Amazon S3 オブジェクトの概要](https://docs.aws.amazon.com/ja_jp/AmazonS3/latest/userguide/UsingObjects.html)

### 4. 例外まで押さえる（`principles_exceptions`）

- 出典: `question_ping-t-76_39629.json#0`
- 問題: Amazon EBSの特徴として正しいものはどれか。
- 対象肢: EC2インスタンスを停止または終了すると、必ず保存データが失われる。
- 分類の判断理由: 停止時にはEBSデータを保持するという基本に加え、終了時だけはボリュームごとの設定で削除・保持が分かれることまで必要である。
- 解説の構成: `停止時の基本 → 終了時の例外条件 → 設定値ごとの扱い`

出力例:

> 間違い。正しくは、EC2インスタンスを停止しても、Amazon EBSに保存したデータは保持される。インスタンスを終了した場合は、各EBSボリュームの`DeleteOnTermination`（終了時に削除）の設定が`true`なら削除され、`false`なら保持される。ルートボリュームは起動時の初期設定で削除されるが、設定を変更すれば保持できる。

公式資料: [EC2インスタンス終了時のデータ保持](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/preserving-volumes-on-termination.html)

### 5. しくみと理由を理解する（`mechanisms_reasons`）

- 出典: `question_keepitup-CLF201C028.json#0`
- 問題: 垂直スケーリングの説明として誤っているものを選んでください。
- 対象肢: インスタンスの性能を上げるだけで、複数の障害ドメインに分散され、システムの可用性も自動的に高まる。
- 分類の判断理由: 用語の定義だけでなく、1台の性能を上げても障害への強さが変わらない構成上の理由が正答の中心である。
- 解説の構成: `垂直スケーリングの動作 → 台数と配置が変わらないこと → 可用性を高める構成`

出力例:

> 間違い。正しくは、垂直スケーリングは、1台のインスタンスに割り当てるCPUやメモリを増やす方法であり、インスタンスの台数や配置場所は増えない。そのため、同じ障害の影響を受けない別々の範囲には分散されず、その1台に障害が起きれば処理が止まる可能性がある。可用性を高めるには、複数のインスタンスを複数のアベイラビリティーゾーンへ配置するなど、障害の影響を分散させる構成が必要である。

公式資料: [AWSにおけるスケーリングの考え方](https://aws.amazon.com/jp/builders-flash/202502/awsgeek-ec2/)

### 6. 順序と流れをつかむ（`sequence_flow`）

- 出典: `question_ping-t-76_39640.json#0`
- 問題: 画像をS3へ保存した直後にLambdaを実行し、メタデータをDynamoDBへ登録するには、どの設定が適切か。
- 見分ける対象: DynamoDBへの書き込み完了をLambda関数のトリガーにすると、処理の順序が逆になる。
- 分類の判断理由: サービスの定義比較ではなく、「何をきっかけに、どの処理が次に動くか」を追うことが中心である。
- 解説の構成: `正しい起点 → 各工程の役割を動作順に接続 → 誤った起点では逆順になる理由`

出力例（`flash_card`の問題単位）:

> 正しい。S3バケットのオブジェクト作成イベントをLambda関数のトリガーにする。処理は、画像をアップロードする → S3に保存される → S3がLambda関数を起動する → Lambda関数がメタデータをDynamoDBへ登録する、という順に進む。DynamoDBへの書き込みは最後の処理であるため、その完了をLambda関数のトリガーにすると順序が逆になる。

公式資料: [Amazon S3イベントをLambdaで処理する](https://docs.aws.amazon.com/lambda/latest/dg/with-s3.html)

### 7. 事例に当てはめて考える（`scenario_application`）

- 出典: `question_ping-t-76_39400.json#0`
- 問題: 数週間だけ使い、稼働中は中断できず、長期契約をしないEC2インスタンスに最適な購入オプションはどれか。
- 見分ける対象: スポットインスタンスは安価だが、AWS側から中断される可能性がある。
- 分類の判断理由: 購入オプションの定義だけでなく、「数週間だけ」「中断できない」「長期契約をしない」という手掛かりを具体的な利用条件へ当てはめる必要がある。
- 解説の構成: `この事例に合う結論 → 判断に使う手掛かり → 条件に合う理由 → 対象肢が合わない理由`

出力例（`group_choice`の問題単位）:

> 正しい。この条件にはオンデマンドインスタンスが適している。判断の手掛かりは、「数週間だけ使う」「稼働中は中断できない」「長期契約をしない」の三点である。オンデマンドインスタンスは長期契約が不要で、利用者が停止や終了の時期を決められる。スポットインスタンスは安価だが、AWS側の空き容量の都合で中断される可能性があるため、この事例には合わない。

公式資料: [オンデマンドインスタンス](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ec2-on-demand-instances.html)、[スポットインスタンス](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/using-spot-instances.html)

### 8. 計算して答えを求める（`calculation`）

- 出典: `question_keepitup-CLF201C044.json#0`
- 問題: 230TBのデータを、1台210TBのAWS Snowball Edge Storage Optimizedで移行するには何台必要か。
- 分類の判断理由: サービス名の知識だけでは判断できず、データ量を1台の容量で割り、端数を切り上げる計算が必要である。具体的な移行事例でも、答えを決める中心操作が計算なのでこの分類を主とする。
- 解説の構成: `求める答え → 公式 → 全変数の意味 → 数値代入 → 途中計算 → 切上げの理由 → 不足量`

出力例（`flash_card`の問題単位）:

> 正しい。AWS Snowball Edge Storage Optimizedは2台必要である。必要台数を\(N\)、移行するデータ量を\(D\)、1台の実効容量を\(C\)とすると、使用する式は次のとおりである。
> \[
> N=\left\lceil\frac{D}{C}\right\rceil
> \]
> \(D=230\,\mathrm{TB}\)、\(C=210\,\mathrm{TB/台}\)を代入すると、
> \[
> \frac{230\,\mathrm{TB}}{210\,\mathrm{TB/台}}=1.095\ldots\,\mathrm{台}
> \]
> データをすべて収めるには端数を切り上げるため、
> \[
> N=\left\lceil1.095\ldots\right\rceil=2\,\mathrm{台}
> \]
> 1台では20TB不足するため、2台が必要である。

公式資料: [Snowball Edgeデバイスの仕様](https://docs.aws.amazon.com/snowball/latest/developer-guide/device-differences.html)、[AWS Snowballのサポート終了案内](https://aws.amazon.com/snowball/)

この計算例は、入力に「Storage Optimizedを2台」という成立する選択肢があり、その肢が正答になっている場合だけ使います。AWS公式仕様と入力が食い違う、又は正解になる選択肢がない場合は03を`blocked`とし、05と02aへ戻します。AWS Snowballは2026年12月31日に商用リージョンでサポート終了予定であるため、説明には実行時点の提供状況を反映します。

`question_keepitup-CLF201C044.json#0`を05で再整備するときは、旧80TBモデルを前提にした「Storage Optimizedを3台」を維持しません。AWS公式仕様の1台210TBに合わせ、230TBを収められる「Storage Optimizedを2台」を選択肢に置いて正答とし、02aで同じ結論を独立に確認します。03は、この上流修正が成立した後にだけ解説を作ります。

## 完成前のAWS確認

- AWS公式資料の現在値と、問題文・選択肢・`correctChoiceText`が同じ結論を示している。
- サービス名を並べただけでなく、初学者が役割、条件、理由、流れ又は判断の手掛かりを追える。
- 主分類は、解説に登場する用語数ではなく、答えへたどり着く中心操作で一つ選んでいる。
- `flash_card`と`group_choice`を対象肢ごとの解説に変えていない。
- 基本解説に必要な情報を補足へ追い出していない。追加価値がなければ補足は0件である。
- 数値、上限、料金、提供状況には、実行時に確認したAWS公式資料を`explanationReferences`として残している。

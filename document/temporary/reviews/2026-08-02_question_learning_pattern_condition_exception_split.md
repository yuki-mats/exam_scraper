# 問題の学び方分類「条件」と「例外」の分割整理

状態: 実装済み
対象: `questionLearningPatternId`の共通分類

## 目的

現在の「条件と例外を押さえる」は、成立条件を理解する問題と、通常とは違う扱いを理解する問題を一つにまとめています。しかし、学習者が「当てはまる条件を覚えている」状態と、「基本のルールに加えて例外まで理解している」状態では、理解の深さが異なります。

この差を解説の書き方と学習分析へ反映できるよう、次の二分類へ分けます。

| ID案 | 表示名 | 判断する内容 | 解説の基本構成 |
| --- | --- | --- | --- |
| `conditions_scope` | 条件を押さえる | いつ、誰に、何に、どの数値・期間・範囲で通常のルールが当てはまるか | 正誤 → 当てはまる条件 → 条件を満たす場合と満たさない場合 |
| `principles_exceptions` | 例外まで押さえる | 普通はどう扱うかと、どの場合だけ違う扱いになるか | 正誤 → 基本のルール → 例外となる条件 → 例外時の扱い |

## 分類の境界

### 条件を押さえる

次のように、条件を満たすと通常のルールがそのまま当てはまる問題を割り当てます。

- 「Aの場合はBとなる」
- 「X以上・未満なら対象となる」
- 対象者、設備、期間、地域、数値又は適用範囲を確かめる

条件を満たすかどうかで結論が決まり、通常とは違う扱いを理解する必要がなければ、この分類です。

### 例外まで押さえる

次のように、基本のルールを理解したうえで、それとは違う扱いになる場合を判断する問題を割り当てます。

- 「原則はAである。ただし、Bの場合はCとなる」
- 「Aを必要とする。ただし、Bを除く」
- 「Bの場合は、この限りでない」
- 免除、除外、特例、みなし規定、経過措置又は代替手段を確かめる

`ただし`、`除く`、`この限りでない`という語だけでは決めません。条件を満たした結果、通常のルールとは違う結論になることを確認します。

## 迷う場合の決め方

一肢を一つの分類へ割り当てます。例外にも発動条件があるため、次の順で判定します。

1. 条件を満たすと通常とは違う扱いになるなら「例外まで押さえる」。
2. それ以外で、数値、期間、対象又は範囲によって通常のルールが当てはまるかを判断するなら「条件を押さえる」。
3. 例外が数値条件で発動する場合も「例外まで押さえる」を優先する。
4. 元の設問が複数の記述をまとめていても、整備後の独立した一肢ごとに分類する。

ガス主任技術者試験の「最高使用圧力が0.3MPa以上、かつ内径が150mm以上の導管を溶接する場合は、溶接施工方法を事前に確認する」は、条件を満たす導管へ通常の規定を適用するため「条件を押さえる」に分類します。

一方、「基準日前4か月以内に漏えい検査を行った場合は、基準日に検査したものとみなす」は、実際の検査日とは違う日付として扱うみなし規定です。期間条件を含みますが、通常とは違う扱いになるため「例外まで押さえる」に分類します。

## 学習者へのフィードバック

分類を分けることで、同じ法令・制度問題の誤答でも、次のように原因を区別できます。

- 「条件を押さえる」が弱い: 数値、期間、対象者又は当てはまる範囲の確認が不足している。
- 「例外まで押さえる」が弱い: 基本のルールは理解しているが、除外、特例又は例外時の扱いまで整理できていない。

前者には条件を表で整理する学習、後者には「原則 → 例外 → 例外時の結論」を対にして復習する学習を提案できます。

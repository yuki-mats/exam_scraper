# 情報セキュリティマネジメント 暗記プラス公開

## 最終目標

情報セキュリティマネジメントの過去問を漏れなく正確に取得し、一問ずつ整備・独立評価した問題データを使って、暗記プラスの情報セキュリティマネジメントアプリを公開する。

ユーザーの依頼は「既存のツールを利用したスクレイピング」から始まり、取得の精査、今後も安定して取得できる改善、問題整備と専用アプリ公開を最終目標とする方針へ拡張された。定期実行は今回は設定しない。

## 完了を判断する証拠

取得元一覧と保存URLの完全一致、本文・選択肢・正答・取得元解説・画像の照合、全対象問題の整備と現行版の別session評価、公開前gate、Firestore・Storage反映後のreadback、アプリの動作確認、ストアの公開状態をそれぞれ証拠で確認する。取得完了、審査提出又は審査待ちはアプリ公開完了と区別する。

アプリ実装は `/Users/yuki/StudioProjects/repaso` の既存release手順を調べて再利用する。既存運用からiOSを最初の公開先と仮定するが、対応プラットフォームとアプリ識別子は設定の現物を確認して確定する。

## 現在の工程

まず取得工程を完了する。sg-siken.comに掲載された年度別過去問は、2016〜2019年度の春秋8回と2023〜2026年度の公開問題4回。予想問題とサンプル問題は、この年度別過去問の取得対象に含めない。午後は共通本文・図表・設問を保持し、同じ解答群から複数を選ぶ欄は一問、異なる名前付き空欄は別問にする。

次に、公式問題の出典と現在の出題範囲を確認し、既存の整備システムで一問ごとに形式、正答、解説、分類を確定し、必要な法令監査と独立評価を行う。旧年度問題の扱いは内容と現行試験への適合性で判断し、年度だけで一括補正しない。

アプリ側はrelease設定、branding、metadata、Firebase、RevenueCat、App Store Connectを確認し、既存アプリの識別子と利用者データを保持したまま新規アプリを準備する。外部反映前に具体的な対象と検証結果を示す。

## 守る条件

- 会話・編集説明は日本語とする。
- リポジトリの `AGENTS.md` と `document/operations/exam_pipeline_manual_and_automation.md` を入口に、責務に合う正本へ進む。
- `00_source` を手作業で改変しない。全件検証済みscraperの更新だけをmanifestへ登録する。既存ID・ファイル名を保全する。
- 問題の正答と解説を別問題から配列順で流し込まない。一問ずつ読んで判断し、機械検証は不整合を検出して止める役割とする。
- 通常のartifactはローカルcheckoutへ保存し、Driveを実行時の参照先にしない。
- exam_scraperは `main` のみ。対象変更だけを内容別にコミットし、`origin/main` へpushする。同時進行の他作業を破棄・巻き戻ししない。
- 定期取得・定期通知のautomationは作成しない。
- 取得・整備・データ公開・アプリ審査提出・アプリ公開を別の完了状態として記録する。

## 進捗の正本

`state.yaml` がtask、receipt、検証状態の正本。新しい仕様はこの実行記録に置かず、既存の責務別正本へ反映する。必要作業が残っている間は最終目標を完了としない。
